# مرجع هنرمندان و پیگیری تکمیل آرشیو

## منبع حقیقت و دامنه

[`artists.json`](artists.json) منبع یکتای دادهٔ هنرمندان این Brand Kit است؛ `schemas/artist-registry.schema.json` قرارداد فیلدها را مشخص می‌کند. رکوردها ۶۵ نام موجود در `catalog/priority-artists-seed.csv` قبلی‌اند که به ساختار پایدار منتقل شدند. آن CSV اکنون فقط سرنخ مهاجرت است و دادهٔ تکراری نگه نمی‌دارد.

این ۶۵ مورد **نامزدهای اولویت تحقیق** هستند، نه هنرمندان تأییدشدهٔ سایت. هیچ دیتابیس یا فهرست کامل سایت در repo نیست. شناسه‌های `AB-CAND-001…065` شناسهٔ داخلی نامزدند، نه ID سایت یا اثبات هویت. نام لاتین، ژانر، دلیل اولویت و snapshot عین دادهٔ صف قبلی و بدون تأیید مستقل نگه داشته شده‌اند. فیلد خالی به معنی ناموجود/نامعلوم است، نه نفی واقعیت.

## وضعیت فیلدهای تکمیل

برای هر رکورد `completion` جداگانه وضعیت این فیلدها را نگه می‌دارد: نام، slug، بیوگرافی، تصویر شاخص، منبع معتبر، لینک رسمی، ارتباط آهنگ/آلبوم، صفحه سایت، عنوان/توضیح SEO، لینک شکسته/تکرار و کنترل کیفیت نهایی. مقادیر مجاز `COMPLETE`, `INCOMPLETE`, `NEEDS_REVIEW`, `VERIFIED`, `UNKNOWN` هستند. این وضعیت‌ها وضعیت کار را توصیف می‌کنند؛ `VERIFIED` فقط پس از درج منبع/مدرک استفاده شود.

`priority` از صف قبلی باقی مانده است و سنجهٔ محبوبیت قطعی نیست. `seed_next_action` متن اولیهٔ صف را برای حفظ سابقه نگه می‌دارد؛ `next_action` اقدام جاری است و با تکمیل هر فیلد باید متناسب با شواهد واقعی به‌روزرسانی شود.

## روال تکمیل

1. نامزد را با منبع رسمی یا معتبر تطبیق دهید؛ برای هم‌نام‌ها رکورد مستقل و یادداشت ابهام نگه دارید.
2. پس از راستی‌آزمایی، alias و slug پایدار و یکتا تعیین کنید؛ شناسهٔ داخلی را عوض نکنید.
3. بیوگرافی را با منبع دقیق، تاریخ مشاهده و بازنویسی اصیل تکمیل کنید؛ تصویر فقط با حق/منشأ روشن.
4. لینک رسمی، آثار و صفحهٔ سایت را فقط پس از آزمون واقعی وارد کنید. عدم وجود دسترسی به سایت باید `UNKNOWN` بماند.
5. قبل از انتشار، SEO، روابط، لینک شکسته، نامزدهای تکراری و کیفیت را جداگانه بررسی کنید.
6. `last_reviewed_on` را فقط برای بازبینی واقعاً انجام‌شده ثبت کنید و منبع را در `source_refs` با URL دقیق، ناشر، نوع و تاریخ دسترسی درج کنید.
